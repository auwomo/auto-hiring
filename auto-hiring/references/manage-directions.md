# 方向管理指南

当用户请求新增、修改或删除招聘方向时，按以下流程操作。

## 触发场景

以下任一情况触发本流程：

1. **明确请求**："新增方向" / "添加 JD" / "加一个方向" / "开一个新岗位"
2. **直接提供 JD 内容**：用户发送一段包含职责/要求/面试安排的文本（即使没说"新增"）
3. **修改请求**："修改 XXX 的 JD" / "更新 XXX 要求" / "换个面试官"
4. **删除请求**："删除方向" / "下线 XXX" / "暂停 XXX 招聘"

## 操作流程

### 新增方向

#### 必填信息（缺一不可，全部收齐才能创建）

| 字段 | 说明 | 来源 |
|------|------|------|
| 方向名称 | 如"运维"、"基模方向" | 用户提供 |
| 职责 | 岗位核心工作内容列表 | 用户提供（JD 文本） |
| 要求 | 硬性条件 | 用户提供（JD 文本） |
| 加分项 | 非必须但加分的条件 | 用户提供或从要求中推导 |
| 一面面试官 | 谁负责一面 | **必须明确问用户** |
| 审批路由 open_id | 一面面试官的飞书 ID | 用户提供或从已有人员中查 |
| 匹配关键词 | 用于简历快速匹配的技术栈关键词 | 从 JD 中提炼，向用户确认 |
| 优先级 | 急/正常/低 | 问用户，默认"正常" |

#### 执行步骤

1. **收集信息**：
   - 如果用户已提供 JD 文本 → 从中提取职责、要求、加分项
   - 如果用户只说了"新增方向" → 询问具体 JD 内容
   
2. **补全缺失字段**（逐项检查，缺什么问什么）：
   ```
   以下信息还需要补充：
   - ❓ 一面面试官是谁？
   - ❓ 审批路由用谁的 open_id？（如果不知道可以先标"待补充"）
   - ❓ 优先级？（急/正常/低）
   ```

3. **提炼关键词**：从 JD 中提取 5-8 个核心技术关键词，向用户确认：
   ```
   我从 JD 中提炼了以下匹配关键词：{关键词列表}
   这些关键词用于简历自动匹配，OK 吗？需要增减吗？
   ```

4. **确认汇总**：在创建前，向用户展示完整信息并确认：
   ```
   即将创建新方向，请确认：
   - 方向名：{名称}
   - 一面：{面试官}
   - 关键词：{关键词}
   - 审批路由：{open_id 或"待补充"}
   - 优先级：{优先级}
   
   确认创建？
   ```

5. **创建文件**：
   - 创建 `directions/<slug>.md`（按下方模板）
   - 在 `directions/_index.md` 注册表新增一行

6. **告知用户**：新方向已生效，可以开始接收简历匹配

#### ⚠️ 阻断规则

- **没有 JD 内容（职责+要求）→ 不创建**，继续向用户要
- **没有一面面试官 → 不创建**，必须知道谁负责一面
- open_id 可以先标"待补充"，但要提醒用户：审批流程暂时无法自动路由

### 修改 JD

1. 读取 `directions/<slug>.md`
2. 根据用户指示修改对应部分（职责/要求/加分项/匹配加分规则）
3. 如果关键词有变化，同步更新 `directions/_index.md` 中该方向的关键词列
4. 确认完成

### 更新面试官/路由

1. 在 `directions/_index.md` 中修改对应方向的"一面面试官"和"审批路由(open_id)"列
2. 如果有共同面试官变动，更新"共同面试官"表
3. 同步更新 `directions/<slug>.md` 中的面试安排
4. 确认完成

### 删除方向

1. 与用户确认要删除的方向
2. 从 `directions/_index.md` 注册表中移除该行
3. 删除 `directions/<slug>.md` 文件
4. 确认完成

## 方向文件模板

```markdown
# {方向名}

## 面试安排

- **一面:** {面试官}
- **二面:** {面试官}
- **三面:** {面试官}

## 职责

1. ...

## 要求

- ...

## 加分项

- ...

## 匹配加分规则

- {条件} → +1 档
- {条件} → +0.5 档
```

## 索引行格式

```
| {方向名} | {slug} | {关键词, 逗号分隔} | {一面面试官} | {审批路由open_id} | {急/正常/低} |
```

## 注意事项

- slug 使用方向中文名或英文简写，与文件名一致
- 关键词要覆盖该方向的核心技术栈（5-8 个），用于简历快速匹配
- 审批路由 open_id 必须是有效的飞书用户 ID，如果不知道则标注"待补充"并提醒用户
- 每个方向文件必须包含"匹配加分规则"部分，用于评估打分
- 匹配加分规则从"加分项"中推导：最核心的 1 条 → +1 档，其余 → +0.5 档

# 简历匹配与评估流程

## Step 1 — 解析 PDF 简历

从用户发送的 PDF 文件中提取以下字段：

| 字段 | 说明 |
|------|------|
| 姓名 | 候选人全名 |
| 学历 | 最高学历、院校、专业、毕业时间 |
| 工作经历 | 公司、职位、时长、主要职责 |
| 技能标签 | 编程语言、框架、工具、领域关键词 |
| 研究方向 | 论文/项目体现的研究领域（如有） |
| 联系方式 | 手机、邮箱 |

如果 PDF 无法直接文本提取，使用 `python3` + `pdfplumber` 或 `PyPDF2` 解析：

```bash
python3 -c "import pdfplumber" 2>/dev/null || pip install pdfplumber -q
```

- 详细职责（用于判断候选人经验是否对口）
- 硬性要求 + 加分项
- 优先级（急/正常/低）

## Step 3 — 匹配算法

对每个方向计算匹配度，考虑以下维度：

1. **技能匹配**（权重 40%）— 候选人技能与岗位要求的重合度
2. **经验匹配**（权重 25%）— 工作年限、行业经验是否符合
3. **学历匹配**（权重 15%）— 学历层次、院校、专业相关性
4. **方向匹配**（权重 20%）— 研究方向/项目经历与团队方向的契合度

输出 Top 1-3 匹配结果，每个包含：
- 匹配方向 + 一面面试官
- 匹配度评分（A/B/C/D）
- 匹配理由（2-3 句）
- 潜在风险或不确定点

### 方向专属加分项

除了通用匹配维度外，每个方向有如下加分信号：

**基模方向：**
- 有 CoRL/ICRA/NeurIPS/ICLR/CVPR 顶会论文 → +1 档
- 熟悉 DreamerV3/UniSim/Genie 任一 → +0.5 档
- 参与过 LLM/MLLM/diffusion 预训练 → +0.5 档

**Post-training：**
- 有 CoRL/RSS/NeurIPS/ICLR 顶会论文 → +1 档
- 有完整 post-training pipeline 经验 → +1 档
- 熟悉 OpenVLA/π0/RoboFlamingo → +0.5 档
- 有 Isaac/Mujoco RL 训练经验 → +0.5 档

**Infra 加速：**
- 有大规模分布式训练/推理落地经验 → +1 档
- 熟练 CUDA/NCCL profiling → +0.5 档
- 深度参与过 vLLM/TensorRT-LLM/SGLang → +0.5 档
- 有 MLSys/OSDI/SOSP/SC 顶会论文 → +0.5 档

**RL 仿真：**
- 有 Sim-to-Real 实践经验 → +1 档
- 熟悉 Isaac Lab/MuJoCo 源码级 → +0.5 档
- 有大规模并行仿真训练经验 → +0.5 档
- 熟悉 URDF/MJCF/USD → +0.5 档

**数据算法：**
- 了解 RLDS/LeRobot/Open X-Embodiment → +1 档
- 有 UE/Isaac/MuJoCo 经验 → +0.5 档
- 有 VLM 自动标注 pipeline 经验 → +0.5 档
- 有游戏引擎仿真资产生产经验 → +0.5 档

### 评分标准（严格）

| 等级 | 定义 | 通过建议 |
|------|------|----------|
| **A** | 核心技能 ≥80% 命中，有直接相关项目经验，学历过硬 | 强烈推荐面试 |
| **B** | 核心技能 60-80% 命中，有相关但非直接经验，可培养 | 可以面试但需考察 |
| **C** | 核心技能 40-60% 命中，经验有一定关联但需较大转型 | 不建议，除非该方向急缺 |
| **D** | 核心技能 <40% 命中，方向不匹配 | 不推荐 |

### 严格红线（出现任一条应在报告中明确标注⚠️）

1. **经验深度不足** — 简历表面覆盖广但每段 ≤1.5年，或工作内容偏应用/调参而非核心研发
2. **跳槽过频** — 5年内 ≥3家公司（排除实习），需标注稳定性风险
3. **外包/派遣身份** — OD、外包、劳务派遣等，需评估实际技术深度是否打折
4. **技能广而不深** — 列了很多技术栈但项目经历无法体现任何一项的深入使用
5. **学历与岗位错配** — 如统计/数据分析背景申请系统/底层开发岗
6. **缺乏核心场景经验** — 对目标方向的核心场景没有实际经历
7. **项目成果模糊** — 只描述做了什么，没有量化结果或技术亮点
8. **技术栈陈旧** — 使用的框架/工具已过时，没有新技术跟进

### 匹配度降级规则

- 触发 1 条红线：最高 B（即使技能表面命中率高）
- 触发 2 条红线：最高 C
- 触发 ≥3 条红线：直接 D

### 评估原则

- **宁严勿宽** — 宁可错过一个还行的人，不要放进来一个不行的人
- **看深度不看广度** — 列了10个技术不如1个做得深
- **看产出不看描述** — "负责xxx"不等于"做出了xxx"，看有没有具体量化成果
- **区分"用过"和"精通"** — 用 PyTorch 跑过 YOLO ≠ 有深度学习研发能力
- **外包经验打折** — OD/外包的项目经验权重 ×0.7（因为通常接触不到核心）

## Step 4 — 生成评估报告

向 HR 输出结构化评估：

```
📋 候选人：{姓名}
🎓 学历：{院校} - {专业} - {学历}
💼 最近经历：{最近公司} - {职位}（{时长}）

🎯 推荐匹配：
1. {方向A}（匹配度: A，一面: {面试官}）— {理由}
2. {方向B}（匹配度: B，一面: {面试官}）— {理由}

✅ 亮点：{1-3 个突出优势}
⚠️ 风险点：{需要注意的地方}

请确认是否进入审批流程？
```

## Step 5 — 等待 HR 确认

- 如果 HR 说"可以"/"通过"/"提交" → 进入流程 B（读取 `references/submit-approval.md`）
- 如果 HR 说"不合适"/"拒绝" → 记录结果，结束
- 如果 HR 要求调整匹配 → 重新评估指定方向

## 注意事项

- 不在对话中暴露完整联系方式（手机+邮箱+姓名组合）
- 评估保持客观中立，不做主观判断（如"这个人很优秀"）
- 如果简历信息不足以做出判断，明确指出缺失信息
